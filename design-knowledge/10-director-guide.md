# ディレクターのための実践ガイド ― 描かないあなたが、デザインを動かす

> 対象：自分では細かく描かないけれど、AIツールやデザイナーに的確に指示を出し、上がってきたデザインを評価・ダメ出しできるようになりたい人。
>
> ゴール：「なんかオシャレにして」を卒業し、「目的・対象・参考・制約・優先順位」で語れるようになること。そして上がってきた画面を、感覚ではなく**言葉**で評価できるようになること。

デザインは才能ではなく、**共通言語**です。描く力がなくても、正しい語彙と観点さえ持てば、あなたは優秀なディレクターになれます。このガイドは「知識の補充」「良い指示の出し方」「デザインの見方」の3本柱で構成しています。

---

## 1. まず知っておきたい前提 ― デザインは「意図の設計」

良いデザインとは、見た目が派手なことではありません。**「誰が・何を・どの順番で見て・何をするか」を設計できている**状態を指します。プロのデザイン批評でも、判断基準はほぼこの5つに集約されます（NN/g の視覚デザイン原則より）。

| 原則 | 一言でいうと | ディレクターの着眼点 |
|---|---|---|
| スケール（大小） | 大事なものを大きく | 一番大きい要素は「一番大事なもの」か？ |
| 視覚的階層 | 見る順番の設計 | 目線が迷わず主役 → 脇役の順に流れるか？ |
| バランス | 重さの釣り合い | 片側だけ重くて傾いて見えないか？ |
| コントラスト | 違いを際立たせる | 主役と背景、文字と地の差ははっきりしているか？ |
| ゲシュタルト（近接・整列） | 関連するものは近く | 意味のかたまりが視覚のかたまりと一致しているか？ |

この5つを頭の隅に置くだけで、「なんか違う」の正体の8割は説明がつきます。

---

## 2. 良い指示の出し方 ― 「オシャレ」は禁句

AIツールもデザイナーも、**曖昧な言葉には曖昧な成果物**で応えます。良い指示には必ず次の5要素が入っています。

### 指示の5要素（GTRCP）

1. **Goal（目的）** ― この画面/成果物で達成したいこと（例：新規登録を増やす）
2. **Target（対象ユーザー）** ― 誰が見るか（例：スマホ中心の30代主婦）
3. **Reference（参考）** ― 近づけたい雰囲気・具体例（例：Airbnbのような余白広めで写真主役）
4. **Constraint（制約）** ― 守るべき条件（ブランド色、載せる情報、サイズ、禁止事項）
5. **Priority（優先順位）** ― 何を一番目立たせ、何を捨てるか

### 依頼文テンプレート（そのまま使えます）

```
【目的】この画面で達成したいこと：____
【対象】主に見る人：____（デバイス：PC / スマホ）
【参考】近づけたい雰囲気：____（URLや「◯◯みたいな」）
【載せる情報】必ず入れる要素：____ / 入れない要素：____
【制約】ブランド色：____ / トーン：____（真面目・親しみ・高級 など）
【優先順位】一番目立たせたいのは：____ / 二番目：____
【避けたいこと】____（例：ごちゃごちゃ、子どもっぽい、安っぽい）
```

### 悪い例 → 良い例（対比集）

| ❌ 悪い指示 | ✅ 良い指示 |
|---|---|
| 「オシャレにして」 | 「余白を広めにとって写真を主役にし、Airbnbのような落ち着いた高級感を出して」 |
| 「もっと目立たせて」 | 「申し込みボタンを一番目立たせたい。色をアクセント色にして、周りに余白を足して孤立させて」 |
| 「情報を全部載せて」 | 「主役は月額料金。特徴は3つに絞り、詳細スペックは下部にまとめて小さく」 |
| 「見やすくして」 | 「見出し・本文・注釈の3段階で文字サイズに差をつけ、行間を1.5倍に広げて」 |
| 「いい感じの色で」 | 「ベース白＋メイン紺（#1E3A5F）＋アクセント橙の3色以内。橙はCTAだけに使って」 |
| 「プロっぽくして」 | 「余白・整列・色数を整えて。要素の左端を1本の線に揃え、色は3色以内に統一して」 |
| 「なんか寂しい」 | 「上部にキャッチコピーと画像を足して情報密度を上げて。ただし1画面1メッセージは守って」 |

**コツ：形容詞（オシャレ・かっこいい）を、名詞と数字（余白・3色・1.5倍・左揃え）に翻訳する。** これができれば指示は激変します。

## 3. デザインを見る観点チェックリスト

上がってきた画面を、この順に上から見ていけば見落としが減ります。各項目「良い/悪いの見分け方」を1行で。

| 観点 | 良い状態の見分け方 | 悪い状態のサイン |
|---|---|---|
| **余白** | 要素の周りに呼吸する隙間があり窮屈でない | ぎゅうぎゅう、端に文字が張り付いている |
| **整列** | 要素の左端（or中央）が1本の見えない線に揃う | 微妙にズレて「なんか気持ち悪い」 |
| **階層** | 目線が主役→脇役の順に自然に流れる | 全部同じ強さで、どこを見ればいいか迷う |
| **色数** | メイン＋アクセント＋無彩色で3〜4色以内 | 5色以上でカラフル、統一感がない |
| **コントラスト** | 文字と背景がはっきり読める（薄すぎない） | 薄いグレー文字が白地で読みづらい |
| **一貫性** | 同じ役割の要素は同じ見た目 | ボタンの形や角丸がバラバラ |
| **密度** | 情報量が適切、詰めすぎず空きすぎず | 情報過多で疲れる／スカスカで不安 |
| **可読性** | 行間・字間・文字サイズが快適 | 行間が詰まって圧迫感、長文が読めない |
| **CTAの明快さ** | 「次に押す場所」が一目でわかる | ボタンが埋もれて見つからない |
| **グルーピング** | 関連情報が近く、無関係は離れている | バラバラで関係性が読み取れない |
| **視線誘導** | 主役が一番大きい/濃い/目立つ | 脇役の飾りが一番目立っている |
| **余韻（トーン）** | 目的の印象（高級/親しみ等）と一致 | 真面目な内容なのに軽薄に見える |

### コントラストの目安（数字で言えると強い）

アクセシビリティの世界標準 WCAG では、本文の文字と背景のコントラスト比は **4.5:1 以上**、大きな文字（約24px以上または太字18px以上）は **3:1 以上**が推奨です。「薄すぎて読みにくい」と感じたら、この基準を根拠に差し戻せます。

### 30秒スクイントテスト（ディレクター必修）

画面を**目を細めて（ぼかして）見る**。ぼやけても最初に目に飛び込む要素が「主役」であるべきもの（見出しやCTA）なら合格。飾りやロゴが一番目立つなら階層が壊れています。描けなくてもできる、最強の評価法です。

## 4. ダメ出しの語彙 ― 「なんか違う」翻訳辞典

ディレクターの価値は、モヤモヤを**具体的な言葉**に変換できること。下の対訳表で、感覚を指示語に翻訳しましょう。

| モヤっと感覚 | 具体的なダメ出し（そのまま伝えてOK） |
|---|---|
| なんか窮屈 | 「要素間の余白が足りない。周囲に余白を足して」 |
| なんか読みにくい | 「行間が詰まりすぎ。行間を1.4〜1.6倍に広げて」 |
| どこ見ればいいか分からない | 「情報の優先順位が不明瞭。主役を1つに絞って大きく」 |
| ごちゃごちゃする | 「アクセント色が多すぎ。色を3色以内に減らして」 |
| 安っぽい | 「余白が狭く要素が詰まっている。余白を増やしフォントを整えて」 |
| 素人っぽい | 「整列が甘い。左端を1本の線に揃えて」 |
| 締まらない | 「コントラストが弱い。見出しと本文の文字サイズ差を大きく」 |
| ボタンが目立たない | 「CTAの視認性が低い。周囲に余白を作り孤立させ、色を変えて」 |
| バラバラに見える | 「一貫性がない。同じ役割の要素のスタイルを統一して」 |
| 関係が分からない | 「グルーピングが弱い。関連要素を近づけ、無関係は離して」 |
| 圧迫感がある | 「情報密度が高すぎ。要素を減らすか、区切って段組みに」 |
| なんか寂しい | 「情報密度が低い。見出し・画像・補足を足して間を埋めて」 |
| チカチカする | 「彩度が高すぎ。色をくすませる（彩度を下げる）」 |
| 子どもっぽい | 「角丸が大きく色が明るすぎ。角を控えめに、色を落ち着かせて」 |
| 古くさい | 「余白が狭く装飾過多。フラットにして余白を広げて」 |
| 文字が飛び込んでこない | 「見出しのジャンプ率が低い。本文との文字サイズ比を1.8〜2倍に」 |

**使い方：「なんか違うんだよね」で止めず、上の右列を1つ選んで伝える。** それだけで手戻りが激減します。

## 5. デザインの基本用語辞典 ― やさしい言葉で

ディレクターが最低限おさえたい用語。難しく考えず、イメージで覚えてください。

| 用語 | やさしい説明 |
|---|---|
| **余白（ホワイトスペース）** | 要素の周りの「何もない空間」。多いほど高級・上品に、少ないほど賑やか・お得感に見える。 |
| **グリッド** | 画面に引く見えない格子。これに沿わせると整列が自動的に決まる。「12分割グリッド」がWebでもFigmaでも定番。 |
| **8pt グリッド** | 余白やサイズを8の倍数（8,16,24,32…）で刻むルール。バラつきが消えて整って見える。 |
| **整列（アライメント）** | 要素の端を一直線に揃えること。左揃えが基本。揃うだけでプロっぽくなる。 |
| **近接（プロキシミティ）** | 関連するものを近づけ、無関係なものを離すこと。線を引かなくても「まとまり」が伝わる。 |
| **視覚的階層** | 大きさ・濃さ・位置で「見る順番」を設計すること。主役→脇役の順に目が流れる状態が理想。 |
| **ジャンプ率** | 一番大きい文字と一番小さい文字のサイズ比。高いほどメリハリ・元気、低いほど落ち着き・上品。 |
| **カーニング** | 文字と文字の間隔の微調整。大きな見出しで詰まって見えるときに広げる。 |
| **行間（リーディング）** | 行と行の縦の間隔。狭いと圧迫、広すぎると散漫。本文は文字サイズの1.4〜1.6倍が快適。 |
| **コントラスト** | 明暗・色・大小の「差」。差が大きいほど目立つ。文字が読めない＝コントラスト不足。 |
| **彩度／トーン** | 色の鮮やかさ。高いと元気・子どもっぽく、低い（くすむ）と大人・上品に見える。 |
| **アクセントカラー** | 一番目立たせたい場所（CTAなど）だけに使う色。使いすぎると効果が消える。 |
| **コンポーネント** | ボタンやカードなど「再利用する部品」。1つ直せば全部直る仕組み。一貫性の要。 |
| **オートレイアウト** | Figmaの機能で、中身が増減すると余白や幅が自動調整される仕組み。手作業のズレが出ない。 |
| **デザイントークン** | 色・余白・文字サイズなどを「名前付きの変数」で管理する仕組み（例：色=primary、余白=space-4）。ブランド統一の土台。 |
| **CTA** | Call To Action。「登録する」「購入」など、ユーザーに押してほしいボタン。最優先で目立たせる。 |
| **KPIカード／スタットカード** | 数字を1つ大きく見せる小さなパネル（例：売上 ¥1.2M）。ダッシュボードの主役。 |
| **F型/Z型** | 人の視線の動くパターン。文章の多い画面はF型、シンプルな画面はZ型。主役はこの通り道に置く。 |

## 6. この自作ツールへの指示のコツ

このプロジェクトのツール（Design Driver）は、**画像を貼るのではなく、編集可能な本物のレイヤーをネイティブ生成**します。用意された部品を組み合わせて画面を組み立てる方式なので、あなたは「どの画面を・どんな雰囲気で・どの情報で」を言葉で伝えるだけで済みます。

### ツールが持っている部品（これらを組み合わせて作る）

| 部品 | 用途 |
|---|---|
| `frame` | 画面や領域の枠（土台のコンテナ） |
| `text` | 見出し・本文・ラベルなどの文字 |
| `rect` | 背景・区切り・帯などの矩形 |
| `table` | 一覧・比較・明細の表 |
| `statCard` / `kpiCard` | 数字を大きく見せる指標カード |
| `donut` | 円グラフ（割合の可視化） |
| `card` / `sidebar` / `sectionHeader` / `button` / `pill` / `input` / `avatar` / `legendItem` / `actionBar` | カード・サイドバー・見出し帯・ボタン・タグ・入力欄・アイコン・凡例・操作バー |

さらに、色・余白・文字サイズは**デザイントークン**（`tokens.mjs`）で一元管理されているので、「トークンに沿って」と言えば自動的に統一感が保たれます。バラバラな指示より、**部品名＋トークン準拠**で頼むほど再現性が上がります。

### このツールへの良い指示例

```
【画面】管理画面のダッシュボード
【参考】Stripeのダッシュボードのような、余白広め・白基調・落ち着いた印象
【載せる情報】
  - 上部に KPIカードを3枚（売上 / 新規ユーザー / 解約率）
  - 中央に donut で売上構成比、右に table で上位5顧客
  - 左に sidebar（ナビ5項目）
【優先順位】KPIカードの数字を最も大きく主役に。表と円グラフは脇役。
【制約】色はトークンのprimary＋accent＋無彩色のみ。8ptグリッドで余白統一。
```

**ポイント：「どんな部品を・いくつ・どこに・どの順で目立たせるか」まで言えば、AIは迷いません。** 逆に「いい感じのダッシュボード」だけだと部品選びが博打になります。参考画面のURLや「◯◯みたいな」を1つ添えるのが最短の近道です。

### 差し戻しも部品語で

- 「statCardの数字が小さい。フォントサイズを1段上げて主役化して」
- 「tableの行間が詰まっている。行の高さを広げて」
- 「donutの色が5色でうるさい。トークンのカラーパレット順で3〜4色に」
- 「frame内の余白が不足。パディングを24pxに」

## 7. 上達の習慣 ― 描けなくても目は肥やせる

デザインを見る目は、**言語化の反復**でしか育ちません。今日からできる習慣を。

- **1日3UI言語化**：好きなアプリ/サイトを3つ見て、「なぜ良いか」を各1文で書く。例「LINEの登録画面はCTAが緑1色で孤立していて迷わない」。
- **悪い例も1日1つ**：使いにくかった画面を「どの観点が壊れているか」で言語化する（例：券売機＝階層が平坦で押す順が不明）。
- **スクイントテストを癖に**：目を細めて「一番目立つ要素」を毎回確認する。
- **色数を数える**：気に入った画面の色を数えてみる。ほとんどが3〜4色以内だと気づくはず。
- **良い依頼文をストックする**：うまくいった指示文を保存し、テンプレとして育てる。
- **before/afterを1つ持つ**：自分の「悪い指示→良い指示」の改善例を1つ言えるようにしておく。

3週間続けると、「なんか違う」が自然と「行間が詰まりすぎ」「アクセント色が多すぎ」に変換されるようになります。それが、描かないディレクターの最強の武器です。

---

## まとめ ― 描かない人こそ、言葉で勝つ

1. **指示は GTRCP**（目的・対象・参考・制約・優先順位）。形容詞を数字と名詞に翻訳する。
2. **評価はチェックリスト＋スクイントテスト**。余白・整列・階層・色数・コントラストを上から順に。
3. **ダメ出しは対訳辞典**で具体語に。「なんか違う」で止めない。
4. **このツールには部品名＋トークン準拠＋参考**で頼めば、再現性高く一発で近づく。

あなたが的確な言葉を持てば、AIもデザイナーも、あなたのビジョンを形にしてくれます。
