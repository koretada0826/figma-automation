# 06 ドメイン別プレイブック: BtoB SaaS 管理画面 / ダッシュボード

> コード生成ツールが参照するための実装粒度プレイブック。数値は Shopify Polaris / Atlassian Design System / IBM Carbon / Ant Design / Material Design など公開の正規デザインシステムから蒸留。BtoB SaaS 管理画面は「情報密度が高く、繰り返し操作され、意思決定を助ける」ことが最優先。装飾より読み取り速度と操作効率を優先する。

---

## 0. 設計原則（BtoB SaaS 特有）

| 原則 | 内容 | 根拠 |
|------|------|------|
| 高密度が正義な場面が多い | 熟練ユーザーが1日中使う業務画面では、余白より一覧性。行を詰め、1画面に多くを収める密度モードを用意する | Carbon は行高を4段階（compact/short/default/tall）用意し、密度を選ばせる |
| 8px グリッド | 余白・寸法は 4/8px の倍数に揃える。Polaris は line-height 20px に合わせ 4px 系トークンで構成 | Polaris Space, Carbon spacing |
| F 型スキャン前提 | ユーザーの視線は左上→右へ、次に左列を下る。最重要情報を左上に置く | 視線追跡研究（top-left が注視の約80%） |
| 一貫性 > 個別最適 | 同じ操作は同じ位置・同じ見た目。テーブル・フォーム・ツールバーの型を固定 | 全DS共通 |
| 状態を必ず設計する | 空・ローディング・エラー・部分読込を「後付け」でなく初期から設計する | Ant Design / Carbon の各コンポーネント状態 |

## 1. 画面骨格（App Shell）

### 1.1 標準寸法

| 要素 | 推奨値 | 備考 |
|------|--------|------|
| サイドバー（フル） | **240–280px** | ラベル+アイコン。日本語ラベルは長めなので 256–280 推奨 |
| サイドバー（アイコンのみ / collapsed） | **72–96px** | Carbon の side-nav rail は 48–64、余裕を持たせるなら 72–96 |
| トップバー高 | **56–64px** | Ant Design Header = 64、Material app bar = 56–64 |
| コンテンツ最大幅 | **1200–1440px**（表中心なら制限なし〜1600） | 読み物系ページは 960–1040 に絞る。データ一覧は横幅いっぱい |
| ページ padding（左右） | **24–32px** | 密度重視なら 24、ゆとり 32 |
| ページ padding（上） | **24–32px** | トップバー直下 |
| カード間ギャップ | **16–24px** | Polaris は 16/20 系 |
| コンテンツ領域の背景 | 薄いグレー（例 #F6F6F7 / #F4F5F7）にカードを白で浮かせる | Polaris/Atlassian のパターン |

### 1.2 3 種のシェル構成

```
[A] 固定サイドバー + トップバー（最も一般的）
┌───────┬──────────────────────────────────────┐
│       │  TopBar  h56–64 (検索/通知/アカウント)  │
│ Side  ├──────────────────────────────────────┤
│ 240–  │  padding 24–32                        │
│ 280   │  ┌ Breadcrumb ─────────────────────┐  │
│       │  │ Page title + primary action     │  │
│       │  │ Content (max 1200–1440 中央寄せ) │  │
│       │  └──────────────────────────────────┘  │
└───────┴──────────────────────────────────────┘

[B] アイコンレール + サブナビ（大規模プロダクト: Jira 型）
┌──┬─────────┬──────────────────────────────┐
│72│ Sub nav │  Content                      │
│–96│ 240–280 │                              │
└──┴─────────┴──────────────────────────────┘

[C] トップナビのみ（機能が浅い / 設定中心の SaaS）
┌──────────────────────────────────────────┐
│ TopBar h56–64  (ロゴ | メニュー | account)  │
├──────────────────────────────────────────┤
│  Content max 1200 中央寄せ                 │
└──────────────────────────────────────────┘
```

- 一次ナビ項目が **7 以上**、または深い階層があるなら [A] か [B]。
- サイドバーは**折りたたみ可能**にし、状態を永続化する。

## 2. ナビゲーション

### 2.1 サイドバー階層

| 項目 | 推奨値 |
|------|--------|
| ナビ項目の高さ | **36–44px**（密度重視 36、標準 40–44） |
| アイコンサイズ | 16–20px、ラベルとのギャップ 8–12px |
| 項目左右 padding | 12–16px |
| セクション見出し（グループラベル） | 11–12px / uppercase or 色薄め / 上に 16–24px マージン |
| ネスト（サブ項目）インデント | 親のアイコン幅ぶん（+28–32px） |
| 最大階層 | **2 階層まで**。3 階層以上は展開式アコーディオンかサブナビ [B] に逃がす |

### 2.2 アクティブ状態

- 現在ページ: **左端に 2–3px のアクセントバー** or 背景ハイライト（薄いブランドカラー 8–12% 不透明）+ 文字/アイコンをブランド色 or 濃色に。
- hover: 背景をわずかに濃く（4–6%）。
- 折りたたみ時: アイコンのみ + ツールチップでラベル表示。

### 2.3 ブレッドクラム

- 使う場面: **階層 2 以上の詳細ページ**、設定の深い画面。ダッシュボードのトップには不要。
- 形式: `一覧 / カテゴリ / 現在ページ`、区切りは `/` または `›`、フォント 12–14px、現在項目はリンクにせず色を落とす。
- ページタイトルの**すぐ上**に配置（上マージン 0、下 4–8px）。

## 3. データテーブル（最重要）

### 3.1 行高・密度（各DSの実測値）

| DS / モード | 行高 | 用途 |
|-------------|------|------|
| Carbon compact | 24px | 極高密度・ログ/数値羅列 |
| Carbon short | 32px | 高密度一覧 |
| Carbon default | 48px | 標準 |
| Carbon tall | 64px | 2行コンテンツ想定 |
| Material dense | 40px | 高密度 |
| Material 標準（行/ヘッダ） | 52 / 56px | 一般的な業務テーブル |

> **推奨レンジ: 行高 44–56px を標準**、密度モードとして **compact 36–40px** を切替可能に。ヘッダ行は本文行と**同じ高さ**に揃える（Carbon の指定）。

### 3.2 セル padding

| 出典 | 水平 padding | 垂直 |
|------|-------------|------|
| Carbon | 左右 16px（先頭・末尾列も16） | 行高で吸収 |
| Ant Design large | 16 / 16 | |
| Ant Design middle | 8 / 12 | |
| Ant Design small | 8 / 8 | |
| Material | セル間 32px 以上、左右 16px | 上下 6px |

> セル水平 padding は **12–16px** を基準。数値列は**右揃え**、テキスト列は左揃え。

### 3.3 罫線・ゼブラ

- **罫線は最小限**。横罫（行区切り）を薄いグレー 1px（例 #E1E3E5）のみ。**縦罫は原則なし**。
- ゼブラ（交互背景）は密度が非常に高い時のみ検討。デフォルトは横罫のみで十分（Polaris は divider で行を区切る思想）。
- ヘッダは背景を薄グレー or 下線 1–2px で本文と分離。ヘッダ文字は 12–13px / 中太 / やや色を落とす。

### 3.4 機能要素

| 要素 | 仕様 |
|------|------|
| ソート | ソート可能列のヘッダに矢印アイコン。クリックで昇順→降順→解除。同時ソートは1列 |
| 選択（チェックボックス） | 先頭に選択列（幅 **32–48px**、Ant は32）。ヘッダに全選択。選択中は**バッチアクションバー**（Carbon: default 48 / small 32px）をツールバー位置に差し替え表示 |
| 行アクション | 末尾列に `⋯` メニュー or hover 表示のインラインアクション。頻用アクションは常時表示 |
| 固定列 | 左に識別子列（名前/ID）、右にアクション列を sticky |
| ページネーション | テーブル下に配置。ページ番号 + 表示件数（10/25/50/100）+ 「X–Y / Z件」。無限スクロールは監査系では避ける |
| 列カスタマイズ | 列の表示/非表示・並べ替えをツールバーの歯車から |

### 3.5 空状態

- テーブル本体に中央寄せの空状態: **アイコン + 見出し + 補足 + 主要CTA**。
- 「データがまだない（初回）」と「フィルタ結果0件」を**区別**する。後者は「条件をクリア」導線を出す。
- 空でもヘッダ行とツールバーは残す（操作を継続できるように）。Ant のデフォルトは空時にページネーションを出さない点に注意し、必要なら維持。

## 4. フォーム

### 4.1 レイアウト規則

| 項目 | 推奨 |
|------|------|
| ラベル位置 | **トップ配置（縦積み）を基本**。入力欄の上、ギャップ 4–8px。左ラベル（横並び）は設定画面など密度重視かつ短ラベル時のみ |
| フィールド高 | 36–44px（トップバー内は40、標準フォーム40–44） |
| フィールド幅 | 入力内容の想定長に合わせる（郵便番号を全幅にしない）。1カラムを基本 |
| 縦間隔（フィールド間） | 16–24px |
| グループ間隔 | 32–40px + セクション見出し |
| 1画面カラム数 | **原則1カラム**。関連する短い項目（姓/名、市区町村など）のみ横並び |
| フォーム最大幅 | 480–640px（読みやすさ優先） |

### 4.2 必須・任意・バリデーション

- **必須表示**: どちらか一方に統一。項目が大半必須なら「任意」だけを `(任意)` と明示、任意が大半なら `*` で必須を示す。赤い `*` は凡例とセットで。
- ヘルプテキスト: フィールド下に 12–13px の薄色で常時表示。
- **バリデーション**: 送信前は入力欄を離れた時（blur）に検証。エラーは**フィールド直下**に赤テキスト + 枠線赤 + アイコン。色だけに頼らない。
- エラーサマリ: 長いフォームは上部にエラー件数サマリ + 各エラーへのアンカー。

### 4.3 送信ボタン配置

| コンテキスト | 配置 |
|--------------|------|
| 単独フォームページ | フォーム下部、**左寄せ**（主ボタン左 / キャンセル右 or リンク）。Polaris/Atlassian は主アクション左傾向 |
| モーダル/ダイアログ | フッター**右寄せ**（キャンセル左 → 主ボタン右）。破壊的操作は主ボタンを赤に |
| 設定ページ（長い） | **sticky フッターバー**で「保存 / 破棄」を常時表示。変更があるまで無効化 |

- 主ボタンは1画面1つ。危険操作（削除等）は確認 + 別色 + 位置を離す。

## 5. KPI カード / ダッシュボード構成

### 5.1 KPI カード仕様

| 要素 | 仕様 |
|------|------|
| カード padding | 16–24px |
| ラベル | 12–14px 薄色（例「今月の売上」） |
| 主数値 | **24–36px 太字**（最重要は40+） |
| 差分/トレンド | ラベル横 or 数値下。前期比を色付き（増=緑/減=赤は文脈次第）+ 矢印 + スパークライン任意 |
| カード高 | 100–140px（数値のみ）、グラフ入りは 240–320px |
| 列数 | デスクトップ **4 列**（各 1/4 幅）、タブレット 2 列、モバイル 1 列 |

### 5.2 配置（F型・ゾーニング）

```
┌──────────────┬──────────────┬──────────────┬──────────────┐
│ 最重要KPI(大) │ 副KPI        │ 副KPI        │ 副KPI        │  ← 横スキャンで3–5指標
├──────────────┴──────┬───────┴──────────────┴──────────────┤
│ 時系列トレンド(左・大) │ 内訳/構成比(右)                       │  ← 左=推移, 右=補足
├──────────────────────┴──────────────────────────────────────┤
│ 詳細テーブル / 直近アクティビティ（下）                        │
└──────────────────────────────────────────────────────────────┘
```

- **左上に主KPIを最大・最高コントラスト**で（「良い/悪い」を即答させる）。
- 横一列トップに **3–5 個**の主要指標。1画面の KPI は **12 個以内**（超えると engagement 低下の報告）。
- 上=概況、中=推移と内訳、下=明細、という上から下への抽象度→具体の流れ。

## 6. フィルタ / 検索 / ツールバー

### 6.1 ツールバー構成（テーブル直上）

```
┌─────────────────────────────────────────────────────────────┐
│ [検索🔍........]  [フィルタ▾][ステータス▾]   [列⚙][エクスポート][＋新規] │
│  左: 絞り込み系                              右: アクション系      │
└─────────────────────────────────────────────────────────────┘
```

| 要素 | 仕様 |
|------|------|
| ツールバー高 | 48–56px（Carbon: default 48 / small 32） |
| 検索ボックス | 左端。プレースホルダで対象明示（「注文番号・顧客名で検索」）。入力はデバウンス 300ms |
| フィルタ | ドロップダウン or 「フィルタ」ボタン→パネル。適用中は**チップ**で可視化 + 個別×とクリア全解除 |
| タブ/セグメント | よく使う定型フィルタは保存ビュー/タブに（例: すべて/未対応/自分の担当） |
| 主アクション | 右端に主ボタン（＋新規作成）。1つに絞る |
| 選択時 | 行選択中はツールバーを**バッチアクションバー**に差し替え（削除・一括編集・エクスポート + 選択解除） |

- フィルタ状態は URL クエリに反映し、共有・リロード耐性を持たせる。

## 7. 空状態・エラー・ローディング

### 7.1 空状態（3種を区別）

| 種類 | 見せ方 |
|------|--------|
| 初回（データ皆無） | イラスト/アイコン + 「まだ〇〇がありません」+ 使い方の一言 + **主CTA**（作成・招待・接続） |
| フィルタ0件 | 「条件に一致する結果がありません」+ **条件クリア**リンク。イラストは控えめ |
| 権限なし | 何が見えないか + 依頼先/管理者への導線 |

### 7.2 ローディング（スケルトン優先）

| 状況 | 手法 |
|------|------|
| 初回・ページ全体 | **スケルトン**（実レイアウトと同形のグレーブロック）。テーブルは行数ぶんのバー、カードはブロック。パルス/シマーで動き |
| 部分更新（フィルタ適用等） | テーブル領域に軽い overlay + スピナー、既存内容は薄く残す |
| 短時間（<300ms） | 何も出さない（ちらつき防止）。300ms〜はスケルトン |
| ボタン処理中 | ボタン内スピナー + 無効化。二重送信防止 |

- スケルトン行数はデフォルトのページ件数（10 など）に合わせる。

### 7.3 エラー

| レベル | 表示 |
|--------|------|
| フィールド | 直下に赤テキスト + 枠赤（4.2参照） |
| セクション/カード | インラインの警告バナー（黄/赤）+ 再試行ボタン |
| ページ全体（取得失敗） | 中央にアイコン + 「読み込めませんでした」+ **再試行**。原因があれば簡潔に |
| 一時通知 | トースト（右上/下）。成功3–4秒で自動消滅、エラーは手動で閉じる |

- **色 + アイコン + テキスト**の3点セット。色だけに依存しない（アクセシビリティ）。

## 8. 情報密度のガイド

| 密度 | 行高 | 余白 | 対象ユーザー |
|------|------|------|--------------|
| Compact | 32–40px | セル padding 8px | 熟練・大量データ・監視/監査 |
| Default | 44–52px | セル padding 12–16px | 一般業務 |
| Comfortable | 56–64px | セル padding 16px+ | 2行コンテンツ・閲覧中心・非熟練 |

- 密度切替はユーザー設定として永続化。**BtoB では Default〜Compact をデフォルト**にするのが妥当（画面あたりの情報量が生産性に直結）。
- 密度を上げても**行の可読性（フォント12–14px、行間確保）とタップ/クリック領域**は落とさない。

| モーダル版 | 幅 480–560、フッター右寄せ、破壊操作は赤主ボタン |

## 10. コード生成チェックリスト

- [ ] 8/4px グリッドに全寸法を丸めたか
- [ ] サイドバー折りたたみと状態永続化があるか
- [ ] テーブルに density 切替・ソート・選択・ページネーション・空状態・スケルトンが揃っているか
- [ ] 横罫のみ / 縦罫なし / ヘッダ行=本文行高 になっているか
- [ ] 数値列右揃え・テキスト列左揃えか
- [ ] フォームはトップラベル・1カラム・必須表示統一・blur バリデーション・sticky保存か
