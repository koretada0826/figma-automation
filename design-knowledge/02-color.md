# カラーシステム設計の教科書

> コード生成ツールが参照するための、実装可能なカラー設計リファレンス。
> Material Design 3 / Radix Colors / Apple HIG / IBM Carbon / Refactoring UI / Tailwind CSS / WCAG の公開ソースを蒸留。すべての16進コードと数値はそのまま実装に使える。

---

## 0. カラーシステムの3層モデル

優れたカラーシステムは「値」を直接使わず、必ず**3つの層**を通す。これはコード生成において最も重要な原則。

| 層 | 名称 | 例 | 役割 |
|----|------|-----|------|
| 1 | **プリミティブ（原色トークン）** | `blue-500 = #3B82F6` | 単なる色の事実。意味を持たない |
| 2 | **セマンティック（意味トークン）** | `--color-primary = blue-500` | 役割に紐づく。UIはこれだけを参照 |
| 3 | **コンポーネント（部品トークン）** | `--button-bg = --color-primary` | 部品固有の割り当て（任意） |

**鉄則**: コンポーネントは絶対にプリミティブ（`#3B82F6`）を直接書かない。必ずセマンティック（`--color-primary`）を参照する。こうすることでダークモード切替やブランド変更が1箇所で完結する。

> Material Design 3 は「color roles（Primary, On-Primary, Surface…）はペイント・バイ・ナンバーの番号であり、UI要素とどの色を置くかを繋ぐ結合組織である」と表現する。IBM Carbon も `interactive-01`, `danger-01`, `layer-01` のような意味ベースのトークンで同じ構造を採る。

## 1. セマンティックカラー（役割と使い分け）

UIで使う色は、見た目ではなく**役割（role）**で定義する。これが全ジャンル共通の骨格。

### 1-1. 全セマンティックトークン一覧

| カテゴリ | トークン名 | 役割 | ライト例 | ダーク例 |
|----------|-----------|------|----------|----------|
| **ブランド** | `primary` | 主要CTA・選択状態・リンク・アクティブ | `#3B82F6` | `#60A5FA` |
| | `primary-hover` | primaryのホバー | `#2563EB` | `#3B82F6` |
| | `on-primary` | primary上の文字/アイコン | `#FFFFFF` | `#0F172A` |
| **背景** | `background` | ページ最背面 | `#FFFFFF` | `#0F172A` |
| | `surface` | カード・シート・メニュー | `#F8FAFC` | `#1E293B` |
| | `surface-2` | 一段上の面（ポップオーバー等） | `#F1F5F9` | `#334155` |
| **文字** | `text` (ink) | 本文・見出し（最高コントラスト） | `#0F172A` | `#F8FAFC` |
| | `text-sub` | 補助テキスト・キャプション | `#475569` | `#CBD5E1` |
| | `text-faint` | プレースホルダ・無効文字 | `#94A3B8` | `#64748B` |
| **境界** | `border` | 区切り線・入力枠 | `#E2E8F0` | `#334155` |
| | `border-strong` | 強調境界・フォーカス外枠 | `#CBD5E1` | `#475569` |
| **状態** | `success` | 成功・完了・正の値 | `#16A34A` | `#4ADE80` |
| | `warning` | 注意・確認が必要 | `#D97706` | `#FBBF24` |
| | `danger` | エラー・破壊的操作・負の値 | `#DC2626` | `#F87171` |
| | `info` | 情報・ヒント | `#2563EB` | `#60A5FA` |

### 1-2. 「On-（前景色）」の概念

Material Design 3 と Apple HIG に共通する重要概念。**すべての背景色にはペアの前景色を定義する**。

| 背景 | ペアの前景（On-） | 用途 |
|------|------------------|------|
| `surface` | `on-surface` (=`text`) | 面の上の本文 |
| `primary` | `on-primary` | 塗りボタンのラベル |
| `danger` | `on-danger` (=`#FFFFFF`) | 削除ボタンのラベル |

これにより「青ボタンに青文字」のようなコントラスト事故を構造的に防げる。

### 1-3. テキスト階層（ink / sub / faint）

Refactoring UI の原則: **色ではなく明度差で階層を作る**。3段階で十分。

| 階層 | 名称 | 明度(L) の目安 | 使う場面 |
|------|------|---------------|----------|
| 1 | ink（本文） | L≈15% | 見出し・本文 |
| 2 | sub（補助） | L≈40% | メタ情報・キャプション |
| 3 | faint（微弱） | L≈65% | プレースホルダ・無効 |

> Refactoring UI: 「テキストの階層は太字や色ではなく、まず明度（グレーの濃さ）で表現せよ」。sub と faint は `text` と同じ色相のグレーを使い、明度だけをずらす。

## 2. カラーランプ（1色を50〜950の階調で持つ）

Tailwind CSS と Radix Colors の中核思想。**1つの色相を10〜12段階に展開**し、UIのあらゆる用途をカバーする。

### 2-2. ランプの段と用途の対応（Radix Colors 12ステップ思想）

Radix は各色相を**12段階**にし、各段に明確な用途を割り当てた。これがランプ設計の教科書的モデル。

| Radix段 | Tailwind近似 | 用途 |
|---------|-------------|------|
| 1 | 50 | アプリ背景 |
| 2 | 50–100 | 微妙な背景 |
| 3 | 100 | コンポーネント背景（通常） |
| 4 | 200 | コンポーネント背景（**hover**） |
| 5 | 200 | コンポーネント背景（**active/pressed**） |
| 6 | 200 | 非インタラクティブ境界（区切り線） |
| 7 | 300 | インタラクティブ境界（入力枠） |
| 8 | 300–400 | 強い境界 / フォーカスリング |
| 9 | 500 | **純色ソリッド**（最高彩度・塗りボタン） |
| 10 | 600 | ソリッドの hover |
| 11 | 600–700 | 低コントラスト文字 |
| 12 | 900 | 高コントラスト文字 |

> Radix: 「9段は全段中で最も彩度が高い純色。11段は低コントラスト文字、12段は高コントラスト文字用に設計され、対応する背景に対して目標コントラスト比を通過するよう作られている」。

### 2-3. ランプの作り方（HSL手法）

Refactoring UI の手法。1色から手作業でランプを作る場合:

1. **基準色（500相当）を決める**。例: `hsl(217, 91%, 60%)` = `#3B82F6`
2. **明るい段**（50〜400）は L を上げる。ただし L を上げるほど彩度 S を**下げ**、色相 H をわずかに回す（黄方向へ+）と自然。
3. **暗い段**（600〜950）は L を下げ、S を**上げ**、H を逆方向に回す。
4. 明度が両端（L≈0% / 100%）に近づくほど彩度の効きが弱まるので、S を積極的に補正する。

> 「純粋なグレーは生命感がない。寒色UIには青み（`#64748B` 系）、暖色UIには黄み・茶み（`#78716C` 系）の彩度をわずかに混ぜよ」。

## 3. コントラストとアクセシビリティ（WCAG）

**測定できないコントラストは実装してはいけない**。WCAG 2.1 の具体基準。

### 3-1. 必須コントラスト比

| レベル | 通常テキスト | 大テキスト | 非テキスト（UI部品/アイコン/境界） |
|--------|------------|-----------|-----------------------------------|
| **AA**（最低基準・推奨） | **4.5:1** | **3:1** | **3:1** |
| **AAA**（強化） | **7:1** | **4.5:1** | — |

- **大テキストの定義**: 18pt（≈24px）以上、または 14pt（≈18.66px）以上の**太字**。
- **非テキスト**（SC 1.4.11）: ボタンの枠、フォーカスリング、アイコン、チャートの線も 3:1 が必要。
- ロゴ、装飾、無効(disabled)状態の要素はコントラスト要件の**対象外**。

### 3-2. 実際の色ペアで検証（白背景 `#FFFFFF` に対して）

| 前景 | コントラスト比 | 通常AA(4.5) | 大AA(3.0) |
|------|--------------|:-----------:|:---------:|
| `#0F172A` (ink) | ≈ 17.9:1 | ✅ | ✅ |
| `#475569` (sub) | ≈ 7.5:1 | ✅ | ✅ |
| `#64748B` (500) | ≈ 4.8:1 | ✅ | ✅ |
| `#94A3B8` (faint) | ≈ 2.6:1 | ❌ | ❌ |
| `#2563EB` (blue-600) | ≈ 5.2:1 | ✅ | ✅ |
| `#3B82F6` (blue-500) | ≈ 3.7:1 | ❌ | ✅ |

**実装ルール**:
- 本文・重要ラベルには **600番以上**を使う（500は本文に不足しがち）。
- `text-faint`（400番）は装飾・プレースホルダ限定。本文には絶対に使わない。
- 塗りボタンの文字は `on-primary`（白 or 900）で必ず 4.5:1 を確保。

### 3-3. 色だけで情報を伝えない（SC 1.4.1）

エラーを「赤」だけで示さない。**アイコン＋テキスト＋色**の3点セットにする。色覚特性のあるユーザーは赤緑を区別できないため。

## 4. 色の使いすぎを避ける（グレー基調＋アクセント1色）

最も効果的で最も守られない原則。

### 4-1. 60-30-10 の比率

| 比率 | 役割 | 色 |
|------|------|-----|
| **60%** | 基調 | 背景・surface（白 / グレー） |
| **30%** | 補助 | text・border（グレー階調） |
| **10%** | アクセント | primary（1色）＋状態色（最小限） |

> Refactoring UI: 「まずグレーだけで（8〜10段のグレーで）UI全体を組み、色は本当に注目させたい場所にだけ足せ」。カラフルなUIは階層が崩壊する。

### 4-2. パレット構成の推奨

```
グレー系ランプ ×1（slate 50–950）  … 背景/面/文字/境界すべて
プライマリ系ランプ ×1（blue 50–950） … CTA・リンク・選択
状態色 ×3〜4（success/warning/danger/info） … 各2〜3段のみ
```

これで**全UIが構築できる**。2つ目の派手なアクセント色を足したくなったら、まず「本当に必要か」を疑う。

### 4-3. アンチパターン

| ❌ やりがち | ✅ 正しい |
|-----------|----------|
| 見出しごとに違う色 | 明度差（ink/sub）で階層化 |
| カードごとに彩色 | グレー面＋1色アクセント |
| 5色以上のブランド色 | 1プライマリ＋状態色 |
| 純黒 `#000` の文字 | `#0F172A` 系のダークグレー |

## 5. 状態色（hover / active / disabled）の作り方

インタラクティブ要素は**同じ色相のまま明度をずらす**ことで状態を表現する。新しい色相は導入しない。

### 5-1. 塗りボタン（primary）の状態設計

| 状態 | 手法 | 例（青） |
|------|------|----------|
| default | 500 or 600 | `#2563EB` (blue-600) |
| **hover** | 明度を1段暗く（−8% L） | `#1D4ED8` (blue-700) |
| **active/pressed** | さらに1段暗く（−16% L） | `#1E40AF` (blue-800) |
| **focus** | defaultのまま＋外側にリング | `+ ring: #93C5FD` 3px |
| **disabled** | 彩度を落とし明度を上げる／不透明度 40% | `opacity: 0.4` or `#94A3B8` |

> ライトモードでは hover は**暗く**、ダークモードでは hover は**明るく**するのが自然（背景との差を広げる方向へ動かす）。

### 5-2. 淡色（ghost/subtle）ボタンの状態

透明背景の要素は、hoverで**薄い塗り**を入れる（Radix の 3→4→5 段の思想）。

| 状態 | 背景 |
|------|------|
| default | `transparent` |
| hover | `#F1F5F9` (slate-100) |
| active | `#E2E8F0` (slate-200) |

### 5-3. disabled の2流派

| 方式 | 実装 | 長所 |
|------|------|------|
| **不透明度** | `opacity: 0.4〜0.5` | 1行で済む・全部品共通 |
| **専用トークン** | bg=`#F1F5F9`, text=`#94A3B8` | 色を精密制御できる |

disabled は WCAG コントラスト対象外だが、faint すぎると「存在に気づかれない」ため 2.5:1 程度は残す。

### 5-4. 状態を作る数式（HSL）

```
hover-bg    = lighten/darken(base, ±8% L)
active-bg   = lighten/darken(base, ±16% L)
disabled    = desaturate(base, -60% S) then lighten(+30% L)
focus-ring  = base の 300 段（例 #93C5FD）を 3px, 半透明50%
```

## 6. ダークモードの考え方

単なる色の反転（invert）ではない。**別テーマとして設計**する。

### 6-1. 純黒を使わない

| ❌ | ✅ | 理由 |
|----|----|----|
| 背景 `#000000` | `#0F172A`（slate-900） | 純黒＋白文字は眩しく、面の重なりを表現できない |
| 文字 `#FFFFFF` | `#F8FAFC`（slate-50） | 純白は強すぎてハレーションを起こす |

> Apple HIG / 各種DS共通: 「`#0f172a` 系の背景は `#000` より柔らかく、微妙な段差でsurfaceを重ねられる」。

### 6-2. 明度で「高さ（elevation）」を表す

ダークモードは影がほぼ見えないため、**面が明るいほど手前**というルールで階層を作る。

| 階層 | ライト | ダーク（明度L） | 用途 |
|------|--------|----------------|------|
| 背景 | `#FFFFFF` | `#0F172A`（L≈10%） | ページ最背面 |
| surface | `#F8FAFC` | `#1E293B`（L≈17%） | カード |
| surface-2 | `#F1F5F9` | `#334155`（L≈26%） | ポップオーバー・モーダル |
| border | `#E2E8F0` | `#334155`〜`#475569` | 区切り |

### 6-3. 彩度を落とす（desaturate）

飽和色（`#FF0000` 等）は暗背景で「振動」して見える。ダークでは**彩度を10〜20%下げ、明度を上げた**バリアントを使う。

| 役割 | ライト | ダーク | 変化 |
|------|--------|--------|------|
| primary | `#2563EB` | `#60A5FA` | 明るく・彩度やや控えめ |
| danger | `#DC2626` | `#F87171` | 明るい赤 |
| success | `#16A34A` | `#4ADE80` | 明るい緑 |
| text | `#0F172A` | `#F8FAFC` | 反転 |
| text-sub | `#475569` | `#CBD5E1` | 反転 |

**原則**: 明るいランプ段（ライトの600）→ ダークでは中間段（400）へスライドする。ランプ設計（第2章）があればこの入れ替えは機械的にできる。

### 6-4. ダークモードのコントラスト注意点

- 白文字 `#F8FAFC` on `#0F172A` ≈ **16:1**（AAA余裕）。
- ただし明るい飽和色 on 暗背景は、明るすぎると逆にコントラスト過剰で疲れる。**AAは満たしつつ7:1前後**に収める。
- 大きな白い面（画像・空白）は避け、面全体の明度を抑える。

## 7. 実装チェックリスト

- [ ] プリミティブ→セマンティック→コンポーネントの3層を分離したか
- [ ] コンポーネントが生の `#hex` を直接参照していないか
- [ ] すべての背景に On-（前景）色をペアで定義したか
- [ ] 本文テキストは白背景に対し 4.5:1 以上か（600段以上を使用）
- [ ] UI部品の境界・アイコンは 3:1 以上か
- [ ] エラーを色だけでなくアイコン＋文言でも伝えているか
- [ ] グレー基調＋アクセント1色に収めたか（派手な色が2つ以上ないか）
- [ ] hover/active は明度ずらし、disabled は彩度落とし＋透明度で作ったか
- [ ] ダーク背景は純黒でなく `#0F172A` 系か
- [ ] ダークの飽和色は彩度を落とし明度を上げたか
- [ ] ライト/ダークで同じセマンティックトークン名を使い回せる構造か
